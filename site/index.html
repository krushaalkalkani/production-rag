Why

A 10-K is a company's annual report to the SEC: a hundred-plus pages of risk factors, segment tables and footnotes. A chatbot over them is easy to demo and hard to trust, because it will happily make up a number that sounds right.

This one answers only from the filings of Apple, Microsoft, NVIDIA, Tesla, Amazon, Alphabet, Meta, JPMorgan, Netflix and AMD. Each sentence points to the passage it came from, a checker deletes any sentence it can't back up, and it says so when the answer isn't there.

What makes it production-grade is measurement: a hand-built test set, an independent grader, and a CI gate that fails the pull request when quality slips.

How it works

  1. 1
    Read the filings

    Download each 10-K from SEC EDGAR, keep the page and the section (Item 1A. Risk Factors) for every line, and cut it into 500-token chunks that overlap by 100.

  2. 2
    Search two ways

    Keyword search finds exact terms like "CET1" or "MI308"; vector search finds meaning ("head office" → "headquarters"). Reciprocal Rank Fusion merges the two rankings.

  3. 3
    Re-rank closely

    A cross-encoder reads the question and each of the 20 candidates together and keeps the best 5. If even the best is irrelevant, the system refuses without calling the LLM.

  4. 4
    Answer, then check

    Claude writes an answer with a chunk id after each sentence. A checker drops any sentence whose cited chunk doesn't contain its numbers and most of its words.

  5. 5
    Gate every change

    On each pull request, GitHub Actions rebuilds the index, runs the test set and fails the build if any score falls under its threshold.

Results

Test set: 63 questions, written and checked against the filings. 52 have an answer, each tied to an exact quote; 11 must be refused (future years, companies not in the corpus, investment advice). An independent model, Claude Opus 5.5, grades the answers through RAGAS.

The quality gate

To prove the gate works, a deliberately bad prompt that drops the grounding, citation and refusal rules was run through the same GitHub Actions check as the normal one (3 companies, 39 questions).

The broken prompt stopped citing, so the checker refused every answer and refusal accuracy fell to 28%. Retrieval stayed at 93%, so the scores point at the part that broke. See the blocked pull request. Thresholds: 85% for faithfulness, refusals and citations; 80% for top 5.

What went wrong

  • Microsoft's sections came out wrong

    Its 10-K repeats "Item 1" as a header on every page, so the parser took a page header for the section start. Now it takes the first line that has a section title and isn't a table-of-contents row.

  • The re-ranker was marked wrong for being right

    JPMorgan states its CET1 ratio in three places and only one was labelled. Test labels are now computed from evidence quotes, and a question can list several.

  • Short correct answers were refused

    "Cupertino, California [AAPL-2026-00056]" was too short to count as a claim, so the checker found nothing to keep. Anything with a citation now counts; a unit test caught it.

  • A metric scored perfect answers 0

    RAGAS FactualCorrectness returned 0 even for exact matches in this setup. Checked by hand against known answers, then switched to AnswerAccuracy, which graded them correctly.
